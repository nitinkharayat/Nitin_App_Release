# Contributing Guide

Thank you for contributing to this project.

This repository is the main development repository for the application. All contributions, improvements, fixes, and new features should be made through this repository.

## How to Contribute

1. Fork this repository.
2. Clone your fork locally.
3. Create a new branch for your changes.
4. Make and test your changes.
5. Push your branch to your fork.
6. Open a Pull Request to this repository.
7. Wait for the maintainers to review your contribution.

## What You Can Contribute

You can contribute to the project in many ways, including:

* Bug fixes
* New features
* UI/UX improvements
* Performance improvements
* Security improvements
* Accessibility improvements
* Documentation
* Tests
* Code refactoring
* Error handling
* Translations
* Build and deployment improvements

## Contribution Rules

Please:

* Keep your contributions relevant to the project.
* Follow the existing code structure and conventions.
* Test your changes before submitting them.
* Keep Pull Requests focused and understandable.
* Write clear commit messages.
* Update documentation when necessary.
* Avoid introducing unnecessary dependencies.
* Respect other contributors and maintainers.

## Pull Requests

When creating a Pull Request, explain:

* What you changed.
* Why you made the change.
* How you tested it.
* Any limitations or additional configuration required.

Small, focused Pull Requests are preferred because reviewing 900 lines of "minor improvements" is how keyboards develop trust issues.

## Issues

Before opening an Issue, check whether a similar Issue already exists.

For bug reports, include:

* A clear description of the problem.
* Steps to reproduce it.
* Expected behavior.
* Actual behavior.
* Relevant error messages or logs.
* Device, operating system, or application version when relevant.

For feature requests, explain the proposed feature and why it would be useful.

## Security

Never commit or publicly expose:

* Passwords
* API keys
* Access tokens
* Private keys
* Authentication credentials
* Database credentials
* Other sensitive information

If you discover a security vulnerability, report it privately to the project maintainers instead of publicly posting sensitive details.

## Deployment

The application may be deployed through the project's configured deployment system.

Contributors should not modify production deployments, deployment credentials, or infrastructure without authorization from the maintainers.

Changes that affect deployment should be clearly documented in the Pull Request.

## Code of Conduct

Contributors are expected to:

* Treat other contributors respectfully.
* Discuss ideas and code professionally.
* Accept constructive feedback.
* Avoid harassment, discrimination, threats, or personal attacks.
* Respect the decisions of project maintainers.

Disagreements about code are normal. Turning them into personal arguments is not a software engineering methodology.
